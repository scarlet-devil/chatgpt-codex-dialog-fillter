# Contributor instructions

Read `README.md`, `PROJECT_MEMORY.md`, and `WORK_LOG.md` before changing this project. Read `docs/HANDOFF.md` before inspecting or modifying a local desktop installation.

## Scope and evidence

- Implement one-way display filtering in ChatGPT. Do not expand this into bilateral history migration or account/storage separation.
- Preserve the Codex view, stored histories, and normal ChatGPT content.
- Do not classify content from titles, assistant nicknames, model names, or the presence of a local working directory alone.
- Record app version, platform, observed metadata, and verification method. Distinguish proposals, cloud checks, and actual local tests.
- Keep private titles, messages, account identifiers, credentials, cookies, and raw personal logs out of this public repository. Use synthetic fixtures.
- Exchange machine-specific reports and evidence through the maintainer's private Drive channel. Public commits and PR text may contain only necessary sanitized conclusions; do not publish raw reports, private Drive links or IDs, machine paths, environment fingerprints, or private code extracts. Keep receipt, document review, static reproduction, and runtime acceptance distinct.
- Do not copy third-party code until its license and attribution requirements have been checked. Links in the research notes are references, not a dependency approval.

## Collaboration

- Use an isolated working branch and a Draft PR. Write commit subjects in English, in the imperative mood. Report progress to the maintainer in Chinese.
- Pin handoffs and review conclusions to a full commit SHA in the PR. Later commits require an updated review scope.
- Update the shared work log with the objective, completed work, evidence, remaining work, tools used, and next action.
- Cloud self-review does not count as independent local verification. Do not attribute work or approval to an agent that has not performed it.
- Keep PRs in Draft until the maintainer authorizes the next stage. Do not merge, release, or install a patch as part of this documentation bootstrap.

These are project instructions, not global identity or system instructions for any contributor.
