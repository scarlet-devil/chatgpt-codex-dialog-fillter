# 本地勘查交接

作者：Alice（云端 ChatGPT Work 环境）。拟接手者：柯蓝（用户本地 Windows 环境）。当前状态：设计待审，未宣称接手者已经接收、执行或同意。

交接基准：Draft PR 正文中的完整 head SHA。后续提交改变范围或方案时，应更新基准及审查结论。

## 已获授权与本次边界

维护者已授权建立公开仓库、提交初稿及建立 Draft PR。本次交付是研究、设计和本地勘查任务；没有发布软件、合并 PR 或安装补丁的授权。此交接只对本项目有效，到本轮可行性结论提交时结束。

唯一产品目标：ChatGPT 界面不出现 Codex 的项目和对话。Codex 界面保持现状，历史数据保持原样。不要把“本地文件夹”或“使用编码模型”当作 Codex 归属证据。

## 第一步：只读勘查

1. 记录真实的应用版本、平台、安装来源及打包形式。公开记录使用脱敏信息，不提交用户名、私有路径、真实项目名或对话内容。
2. 核对当前构建是否已有官方可用的显示设置。如果已经满足验收条件，报告证据并停止补丁实施。
3. 找到顶层 ChatGPT/Codex 视图切换标记，并明确它与普通聊天、ChatGPT Work、模型选择之间的关系。
4. 找到项目与对话的可靠来源/归属标记，用合成样例说明哪些判断已证实、哪些未知。特别检查本地 ChatGPT Work 项目及混合容器。
5. 列出项目、置顶、最近对话、搜索、展开子列表等实际入口，以及分页、缓存、动态刷新和切换模式时的渲染过程。
6. 评估 `DESIGN.md` 两条候选路线的可行性，记录可逆性、版本兼容检查和首次渲染泄露风险。不要为勘查关闭安全保护或对外暴露调试端口。

## 回传内容

- 基准 SHA、实际环境和检查方法。
- 视图及归属判断的证据，字段名或静态代码位置与脱敏样例；未知项明确标为未知。
- 建议的最小实现位置、兼容性边界和可验证的回滚方式。
- 对每条验收条件的可实现性判断；如果只能覆盖部分列表或有短暂闪现，明确写出。
- 结论：可实施、需调整设计，或当前构建不支持。独立本地结论不能由 Alice 的云端自检替代。

保持 Draft，使用英文 commit；在同一 PR 中记录后续结论与精确 SHA，并更新 `WORK_LOG.md`。不得把待执行步骤写成已完成测试。
